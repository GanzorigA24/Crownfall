# Crownfall – Project Work Plan

**Project Name:** Crownfall  
**Created By:** Ganzorig Arvinbileg  
**Project Type:** 2D Fantasy Real-Time Strategy Game  
**Game Engine:** Unity 6.6  
**Programming Language:** C#  
**Project Purpose:** Game Development and QA Portfolio  
**Version:** 0.1  
**Status:** Planning

---

## 1. Project Overview

Crownfall is a 2D fantasy real-time strategy game inspired by classic kingdom and army management games.

The project will be developed using Unity and C#. The initial version will focus on offline gameplay, where one player competes against a basic AI opponent.

The main objective is to build a functional game while gaining practical experience in game development and software quality assurance.

The project will also serve as a portfolio project to demonstrate manual testing, exploratory testing, test documentation, bug reporting, and basic test automation.

## 2. Project Objectives

### Game Development Objectives
- Learn Unity Editor and basic C# programming.
- Build a functional 2D strategy game.
- Implement resource management and unit recruitment.
- Develop unit movement and automatic combat.
- Implement player commands and basic AI behavior.
- Create a playable game with victory and defeat conditions.

### QA Objectives
- Create a professional Test Plan.
- Develop Test Scenarios and Detailed Test Cases.
- Perform functional and exploratory testing.
- Identify, reproduce, and document software defects.
- Perform regression testing after bug fixes.
- Learn and implement basic automated tests using Unity Test Framework.
- Maintain testing evidence and documentation on GitHub.

## 3. Development Scope

### Version 0.1 – Offline Prototype

The first version will include:

- One playable battlefield.
- Two opposing castles.
- Gold resource system.
- Miner recruitment and gold collection.
- Swordsman and archer recruitment.
- Basic unit movement.
- Automatic combat.
- Attack and defend commands.
- Castle health system.
- Basic AI opponent.
- Victory and defeat conditions.
- Basic game interface.

### Future Features (Not Included in Version 0.1)

The following features may be considered after the first version is completed:

- Online 1v1 multiplayer.
- Private multiplayer rooms.
- Online matchmaking.
- Additional unit types.
- Multiple maps.
- Unit upgrades and special abilities.
- Ranking system.
- Advanced AI.
- Additional game modes.

These features are outside the initial development scope.

## 4. Development Roadmap

### Phase 1 – Unity Fundamentals
**Estimated Time:** 2–3 days

Tasks:
- Understand the Unity Editor interface.
- Learn GameObjects and Components.
- Understand Transform, Rigidbody2D, and Collider2D.
- Learn Scenes and Prefabs.
- Learn basic C# scripting.
- Understand Unity Console and debugging.

Deliverables:
- Organized Unity project.
- Main game scene.
- Basic objects and physics exercises.

### Phase 2 – Game Design and Project Setup
**Estimated Time:** 1 day

Tasks:
- Finalize the Game Design Document.
- Organize project folders.
- Create the battlefield.
- Set up player and enemy sides.
- Prepare basic game assets.

Deliverables:
- Game Design Document.
- Basic battlefield scene.
- Organized GitHub repository.

### Phase 3 – Core Gameplay Development
**Estimated Time:** 4–6 days

Tasks:
- Implement gold collection.
- Create miner recruitment.
- Implement swordsman and archer recruitment.
- Develop unit movement.
- Implement automatic combat.
- Add attack and defend commands.
- Create castle health and damage systems.
- Implement victory and defeat conditions.

Deliverables:
- Functional resource system.
- Recruitable units.
- Working combat system.
- Basic playable match.

### Phase 4 – AI and User Interface
**Estimated Time:** 2–3 days

Tasks:
- Create a basic AI opponent.
- Implement AI recruitment and attack behavior.
- Create the main menu.
- Create the gameplay interface.
- Add pause and restart functionality.
- Create victory and defeat screens.

Deliverables:
- Playable Player vs AI game.
- Functional user interface.

### Phase 5 – Manual QA Testing
**Estimated Time:** 3–4 days

Tasks:
- Create a Test Plan.
- Develop Test Scenarios.
- Write approximately 20–30 Detailed Test Cases.
- Perform functional testing.
- Perform exploratory testing.

- Capture screenshots and evidence.

Deliverables:
- Test Plan.
- Test Scenarios.
- Detailed Test Cases.
- Bug Reports.
- Test Execution Report.
- Testing evidence.

### Phase 6 – Test Automation
**Estimated Time:** 2–3 days

Deliverables:

- Automation documentation.

### Phase 7 – GitHub and Portfolio Finalization

Tasks:
- Organize the final project structure.

Deliverables:

## 5. Estimated Project Timeline

The initial target is approximately 3–5 weeks, assuming around 2–3 hours of focused work per day.

The timeline is an estimate and may change depending on development challenges, learning progress, and bug fixing.

Priority will be given to completing a functional game and meaningful QA documentation rather than adding unnecessary features.

The repository will contain:

- Assets: Game artwork, audio, and other resources.
- Scenes: Unity game scenes.
- Scripts: C# game logic.
- Prefabs: Reusable game objects.
- Tests: Automated test scripts.
- Documentation: Project and QA documentation.
- Evidence: Screenshots and testing videos.

## 8. Definition of Project Completion

Version 0.1 will be considered complete when:

- The game can be launched and played.
- The player can collect resources and recruit units.
- Units can move and fight.
- The AI opponent can perform basic actions.
- The player can win or lose a match.
- Main gameplay features have been manually tested.
- Test cases and actual results are documented.
- Identified defects are recorded.
- Basic automated tests are implemented.
- The GitHub repository contains the project and its documentation.

## 9. Working Approach

The project will follow an incremental development and testing approach.

Each major feature will be developed, tested, and reviewed before moving to the next feature.

Development progress will be tracked using GitHub commits. Testing documentation and evidence will be maintained throughout the project.

The initial focus is to complete a small but functional offline game. Multiplayer and other advanced features will only be considered after Version 0.1 is completed.
